Key rule decisions (so nobody makes coaching judgment calls)

  • Increase: all working sets hit target, min RIR ≥ 2 or unrecorded → round5(w × 1.05), at least +5, at most +20%. 380→400, 120→125, 160→170, 50→55 per hand.
  • Reduce: target hit but any working set RIR ≤ 1 → round5(w × 0.95). Bench 185 (RIR 0) → 175.
  • Jump too big: miss after a >50% jump within a session → Brzycki estimate for target+2 reps. Chest press 180×6, target 10 → 145.
  • Skipped last time: reinstate one step up; kettlebells use a ladder (45 → 53).
  • Session type: layoff (>10 days) → re-entry; else heavy unless the last heavy/re-entry session was <48 h ago → light. Poor sleep or ≥2 significantly sore areas swaps heavy → light. Rotation phases (Upper/Lower) take the next type after the last one done, so missed days never advance them.
  • Duration: computed by estimateDuration and overwrites the model's estimate.
  • RIR "1–2" is stored as 1.

Model usage

  • MODELS.routine = claude-sonnet-5-5 (plan, refine, review, conversation). MODELS.deep = claude-opus-5-5 (program review, research). Env-overridable.
  • Structured output via client.messages.parse + zodOutputFormat; validate, retry once on failure.
  • Research: server tool { type: "web_search_20260209", name: "web_search", max_uses: 5 }; collect sources from web_search_tool_result blocks and text citations. A search error comes back as a result block, not an exception. When Client.webResearch is false, no tool; the note says no research was run.
  • Conversation: tool use with tool_choice: auto (forced tool choice is a 400 on these models). Tools: plan_today, refine_plan, save_preference, save_consideration, update_schedule, save_checkin, review_session, start_program_review, research.

Rules for managers

  • Split work into Haiku-sized tasks: one file or function, exact inputs/outputs/types, file path, and a check that proves it's done. Paste the relevant contract snippets into each task.
  • No coaching judgment calls in worker tasks. Philosophy comes from philosophy.ts or the task spec.
  • After each worker task: npm run typecheck (scoped to owned files while other workstreams are in flight), npm test. Send failures back with the output.
  • Small commits per task. Never commit .env or prisma/dev.db. Never delete existing data or templates.
  • Tests needing a DB use DATABASE_URL=file:./test.db + prisma migrate reset --force --skip-seed on the test file only. Never touch dev.db from tests.
  • Report: what changed, what's tested, any contract deviations.
